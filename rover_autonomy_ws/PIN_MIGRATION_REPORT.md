# Pi 모터 / Uno 센서 분리 결과 — 2026-11-13

> 후속 UART 배포 작업에서 Pi 전송·ROS 빌드·가상 통합 시험과 실제 pigpiod의 PWM 0/정지 감시 검증을 수행했습니다. 통신은 USB에서 GPIO14/15 UART(`/dev/serial0`)로 바꿨습니다. 아래는 최초 로컬 전환 시점의 기록이며, 이후 결과는 UART_DEPLOYMENT_REPORT.md를 기준으로 합니다.

사용자의 최신 배선을 기준으로 로컬 코드를 변경했습니다. 왼쪽 PWM GPIO12/18, 오른쪽 GPIO13/19를 각각 공유 채널로 제어하며, 2번 BIN1=GPIO9, BIN2=GPIO11입니다. 오른쪽 AIN2는 HAT ID 예약 GPIO0 대신 GPIO23으로 배정했습니다. 실제 결선도 이 변경을 따라야 합니다. 전체 표는 WIRING.md에 있습니다.

## 변경 사항

- Pi 4용 pigpio 하드웨어 PWM0/1을 사용합니다. PWM 입력 네 개를 각 GPIO에 따로 연결하고, 같은 쪽 두 핀에 동일 듀티/주파수를 적용합니다. A/B 방향 입력은 각각 분리했습니다.
- 좌우 PID와 네 엔코더 각각의 정지/역방향 감시를 Pi로 옮겼습니다. 모터 방향 부호와 엔코더 부호는 LF RF LR RR 순서로 별도 설정합니다.
- Uno는 RA2 센서 전용 펌웨어로 변경했습니다. 엔코더 8개 신호핀, 초음파 A0/A1, IR D8~D12를 읽으며 초음파 TRIG 이외에 모터/센서 신호핀을 출력하지 않습니다.
- USB 데이터는 `S sequence sample_us LF RF LR RR range_mm flags ir_mask`이며 50ms 주기입니다. Pi는 Uno 샘플 시간으로 RPM을 계산하고 uint32 계수/시간 순환을 처리합니다.
- 이전 RA1/EM2 펌웨어는 식별 단계에서 거부합니다. 이전 두 .ino 경로도 의도적으로 컴파일을 차단하여 새로운 `firmware/rover_sensors` 경로를 안내합니다. 기존 보드 flash는 아직 변경하지 않았습니다.
- base_node와 motor_bench_test를 Pi GPIO 출력으로 전환했습니다. 벤치와 주행이 동시에 GPIO를 점유하지 않게 파일 잠금을 유지합니다.
- Pi 제어 루프 지연, USB 오류/보드 재시작/센서 시간 오류, 잘못된 목표값은 정지 및 재활성화 요구로 처리합니다. 전면 초음파 130mm 이내·무효·오래된 값에서도 출력을 차단합니다.
- 별도의 pigpiod 스크립트는 제어 하트비트가 약 250ms 끊기면 STBY를 LOW로 내리고 종료합니다. 프로세스가 죽은 뒤 남은 감시 스크립트는 다음 소유자가 식별해 정리하도록 했습니다. 실제 Pi에서 스크립트 실행과 정지 시간 검증이 필요합니다. OS·pigpiod 자체 고장에 대한 하드웨어 차단은 아닙니다.
- IR 원시값 `/rover/ir_raw`와 극성을 적용한 `/rover/ir`을 추가했습니다. 주행의 라인 판단은 기존 카메라 기준입니다.
- 이전 RA1 통신은 `legacy_protocol.py`로 격리해 오프라인 회귀시험만 보존합니다. 메모리 시험용 가상 통신은 RA2 센서 프로토콜로 변경했습니다.
- 기본 출력 비활성 및 미보정 상태를 유지했습니다. Pi 배포 묶음에는 현재 RA2 hex만 포함하며 오래된 모터 펌웨어 바이너리는 포함하지 않습니다.

## 로컬 검증

- 기존 수정 전 기준: pytest 111개 통과.
- 변경 후: pytest **148개 통과**, Ruff 오류 없음. 새 Pi/센서 전환 테스트는 37개입니다.
- 새 검증 범위: 식별·분할 패킷·잘못된/중복 패킷·센서 시계 순환·보드 재시작·명시적 활성화·초음파 차단·샘플 사이 정지·USB/제어 루프 고장·개별 엔코더 이상·네 PWM 핀의 채널별 듀티·모터별 방향 부호·감시 고장·핀 중복/예약 핀 검출.
- Arduino Uno RA2 펌웨어 컴파일 성공: flash 4,660 / 32,256 bytes (14%), 정적 RAM 347 / 2,048 bytes (16%). 새 보드 업로드는 수행하지 않았습니다.
- Windows에서 Python 구문 검사와 설정 검사를 통과했습니다. rclpy·Picamera2·실제 pigpiod가 없는 환경이며 ROS 통합/물리 GPIO 출력 검증을 대신하지 않습니다.
- RA2 메모리 시험 도구도 갱신했습니다. 이전 메모리 보고서를 새 Pi PWM 구현의 장시간 검증 결과로 사용하지 않습니다.
